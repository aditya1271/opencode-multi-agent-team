## Search

- Your code-search tools first (under **Your tools**, if any), then grep, glob and read.
- First judge whether the request touches known files or needs wider search; keep small, targeted requests on a light path.
- Trace the relevant code path; don't stop at file names that match.
- Look for an existing pattern or similar feature the change should follow.
- For a failure, start from the exact error text and the code it points to.
- Keep observed facts apart from guesses, and note the evidence behind your decision.
- Read only what you need to decide and to write the brief.

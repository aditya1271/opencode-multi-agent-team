## Polished request

- **Goal**: what the user actually wants, in their words, not the first code location they mention.
- **Scope** (files, components, what is out of scope)
- **Constraints**: the user's requirements. Keep suggested implementation details apart from hard requirements.
- **Done when** (how to tell it worked, e.g. the build or test that must pass)
- **Unclear points** (only if any): ambiguities that would change the implementation, and your guesses. Don't fill them in silently.

Keep it short and actionable; no extra prose.
